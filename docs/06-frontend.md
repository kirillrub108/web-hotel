# 06. Frontend

## Nuxt 4 и каталог app

В Nuxt 4 корнем исходников по умолчанию является каталог `app/`. Поэтому страницы, компоненты, стили и точка входа лежат в `frontend/app/`, а в корне `frontend/` остаются только конфиги, `public/` и манифесты пакетов. Это не самодельная раскладка, а дефолт фреймворка; переопределять его ради привычного вида не стали.

```
frontend/
├── nuxt.config.ts          # прокси /api/**, подключение стилей, опрос файлов
├── tsconfig.json           # extends ./.nuxt/tsconfig.json
├── package.json            # nuxt, vue, vue-router, typescript — и всё
├── package-lock.json       # нужен для npm ci в Dockerfile
├── public/images/rooms/    # шесть SVG-плейсхолдеров
└── app/
    ├── app.vue             # AppHeader + NuxtPage + AppFooter
    ├── types.ts            # интерфейсы Hotel и Room
    ├── assets/css/main.css # переменные и общие классы
    ├── components/
    │   ├── AppHeader.vue
    │   ├── AppFooter.vue
    │   ├── RoomCard.vue
    │   └── BookingForm.vue
    └── pages/
        ├── index.vue
        ├── contacts.vue
        └── rooms/
            ├── index.vue
            └── [slug].vue
```

Каталога `layouts/` нет: макет ровно один, и он живёт прямо в [app.vue](../frontend/app/app.vue). Нет также `stores/`, `plugins/`, `middleware/` и `composables/` — ни один из этих слоёв не понадобился бы ничем, кроме собственного существования.

## Роутинг

Файловый, без единой строки конфигурации: `pages/index.vue` даёт `/`, `pages/contacts.vue` даёт `/contacts`, `pages/rooms/index.vue` даёт `/rooms`, а `pages/rooms/[slug].vue` даёт `/rooms/:slug`.

## Работа с данными

Ровно один способ: `useFetch` по относительному пути.

```ts
const { data: hotel } = await useFetch<Hotel>('/api/hotel', { key: 'hotel' })
```

Ключ `hotel` указан намеренно. Данные гостиницы нужны подвалу, главной странице и странице контактов; общий ключ заставляет Nuxt переиспользовать один результат вместо трёх одинаковых запросов на рендер страницы. Это то место, где в более крупном проекте появился бы store — здесь хватило ключа.

Типы ответов описаны один раз в [types.ts](../frontend/app/types.ts) и импортируются как `import type`. Тип `any` в проекте не встречается; единственное место с приведением — разбор ошибки в форме заявки, и оно сужено до `{ data?: { detail?: unknown } }`.

## Компоненты

| Компонент | Ответственность |
|---|---|
| [AppHeader.vue](../frontend/app/components/AppHeader.vue) | Логотип, навигация, раскрытие меню на узком экране через один `ref` |
| [AppFooter.vue](../frontend/app/components/AppFooter.vue) | Контакты и время заезда, берёт их тем же `useFetch` с ключом `hotel` |
| [RoomCard.vue](../frontend/app/components/RoomCard.vue) | Карточка номера для сеток на главной и в каталоге |
| [BookingForm.vue](../frontend/app/components/BookingForm.vue) | Форма заявки: состояние, валидация, отправка, успех и ошибка |

Компоненты Nuxt импортирует автоматически, явных импортов в страницах нет.

`BookingForm` держит четыре флага состояния: `errors` (ошибки полей), `serverError` (плашка с ответом сервера), `isSent` (форма заменена подтверждением) и `isSending` (кнопка заблокирована на время запроса). Форма получает объект номера через props, поэтому знает вместимость и может проверить число гостей до отправки.

Отправка идёт через `$fetch`, а не `useFetch`: это разовое действие по нажатию кнопки, а не загрузка данных страницы, и кэширование с повтором при гидратации здесь не нужны.

## Стили

Один файл [main.css](../frontend/app/assets/css/main.css) объявляет палитру, шкалу отступов, радиусы и тень в CSS-переменных, а также общие классы: `.container`, `.section`, `.grid`, `.card`, `.button`, `.field`, `.notice`, `.tag`. Всё остальное — `<style scoped>` внутри компонентов, поэтому имена классов не конфликтуют между файлами.

Палитра тёплая: кремовый фон, тёмно-коричневый текст, терракотовый акцент. Адаптивность держится на `grid` с `auto-fill` и `minmax` плюс несколько медиазапросов на 560, 700, 800 и 900 пикселей. Иконочных пакетов и CSS-фреймворков нет.

Изображения номеров — SVG, нарисованные в проекте: заливка своим цветом, схематичное окно с мебелью и подпись категории. Внешних адресов нет ни одного, сайт полностью работает без интернета.
