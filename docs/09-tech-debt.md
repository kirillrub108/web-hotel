# 09. Слабые места и техдолг

Раздел описывает, чего в системе нет и где она может подвести. У каждого пункта указан статус: **осознанное ограничение** — решение принято и цена известна; **долг** — это стоит исправить.

## Закрыто в этой версии

| Было | Стало |
|---|---|
| Две заявки на один номер на одни даты создавались обе | Подтверждённые заявки закрывают даты; гарантию даёт ограничение базы `bookings_no_overlap` |
| Заявки видны только через psql | Админка на `/admin` со входом, фильтром и сменой статуса |
| Принимались даты заезда в прошлом | 422 на сервере и подсказка на клиенте |
| Телефон проверялся только по длине строки | Проверяется число цифр: от 10 до 15 |
| Эндпоинт заявок ничем не ограничен | Лимит по IP и общий потолок на сайт |
| Схема создавалась `create_all`, изменение требовало `down -v` | Миграции Alembic |
| Нет индекса на `bookings.room_id` | Индекс есть |
| Тесты работали с рабочей базой, успешная заявка не тестировалась | Отдельная база `hotel_test`, двадцать восемь тестов |

| Опрос файлов включён всегда | Переменная `WATCH_POLLING` |
| Нет языка страницы, favicon, русской страницы ошибки | Есть |

## Безопасность и злоупотребления

**Лимит по IP обходится подделкой заголовка.** *Долг, пока контейнеры в dev-режиме.* Dev-сервер Nuxt пропускает присланный клиентом `X-Forwarded-For`, поэтому каждый запрос может назваться новым IP. Поток спама всё равно упирается в общий потолок: тридцать заявок за десять минут на весь сайт. Обратная сторона потолка — атакующий может исчерпать его и на десять минут закрыть форму для настоящих гостей. Исправляется при переходе на продакшен-сборку за reverse proxy, который сам выставляет `X-Forwarded-For`, см. [04-backend.md](04-backend.md).

**Счётчики лимитов живут в памяти процесса.** *Осознанное ограничение.* Они обнуляются при перезапуске и не работают при нескольких процессах uvicorn. Для нескольких процессов понадобится общее хранилище, например Redis.

**Один администратор, пароль в переменной окружения.** *Осознанное ограничение.* Нет таблицы пользователей, хешей паролей и журнала, кто подтвердил заявку. Когда администраторов станет несколько, понадобятся учётные записи и запись автора изменения статуса.

**`SECRET_KEY` по умолчанию случайный.** *Осознанное ограничение.* Без заданного ключа каждый перезапуск backend разлогинивает администратора, а в dev-режиме перезапуск случается после каждой правки кода. Решается строкой в `.env`.

**Cookie сессии без флага `Secure` по умолчанию.** *Осознанное ограничение.* Сайт пока работает по HTTP, и cookie с `Secure` браузер просто не отправил бы. Когда появится HTTPS, нужно выставить `COOKIE_SECURE=true`.

**Пароль базы по умолчанию `hotel`.** *Осознанное ограничение.* Порт базы открыт только на `127.0.0.1`, поэтому снаружи к ней не подключиться. На общей машине пароль стоит сменить в `.env`.

## Функциональность

**О новой заявке никто не узнаёт сам.** *Долг.* Администратор видит заявку, только открыв `/admin`. Уведомления по почте или в мессенджер нет. Гость тоже не получает письма ни о приёме, ни о подтверждении заявки.

**Содержимое сайта меняется только в коде.** *Осознанное ограничение.* Цены, описания и доступность номеров задаются в `seed.py`, но сид работает только на пустой базе. На работающем сайте менять их нужно миграцией с `UPDATE` или через psql.

**Нет ограничений на длину проживания и горизонт брони.** *Долг.* Заявка на год вперёд на двести ночей будет принята. Правило видно из тела запроса и должно жить в Pydantic.

**«Сегодня» считается по UTC.** *Осознанное ограничение.* В первые три часа суток по Москве сервер примет заявку на вчерашнюю дату. В коде помечено `ponytail`.

**Постраничный вывод в админке через `offset`.** *Осознанное ограничение.* Если между переходами по страницам придёт новая заявка, одна строка сдвинется и покажется дважды. При объёмах гостиницы это незаметно.

**Почта проверяется простым регулярным выражением.** *Осознанное ограничение.* Грубые ошибки ловятся, но многие неработающие адреса проходят.

**Удобства номера хранятся в JSON.** *Осознанное ограничение.* По ним нельзя фильтровать, опечатка в названии не ловится.

## Инфраструктура

**Контейнеры работают в режиме разработки.** *Осознанное ограничение, по решению владельца проекта.* Uvicorn с `--reload` и dev-сервер Nuxt медленнее собранной версии и дают подробные стектрейсы в логах. Нет reverse proxy, TLS, политики перезапуска, резервного копирования тома и мониторинга.

**Нет резервных копий базы.** *Долг.* Заявки гостей теперь представляют ценность, а живут только в томе `db-data`. Минимум — регулярный `pg_dump` по расписанию на хосте.

**Типы фронта не проверяются автоматически.** *Долг.* В проекте нет `vue-tsc` и шага `nuxi typecheck`. Dev-сервер Nuxt собирает код без проверки типов, и новая ошибка типа обнаружится только в редакторе. Текущая версия проверена вручную командой `vue-tsc -b --noEmit`, ошибок нет.

## Тесты

**Тесты опираются на данные сида.** *Осознанное ограничение.* [test_api.py](../backend/tests/test_api.py) ищет номер `lyuks`, считает, что стандарт идёт вторым, и ожидает столько номеров, сколько в `seed.ROOMS`. Перестановка номеров в сиде потребует правки константы в тестах.

**Нет тестов фронта.** *Долг.* Форма заявки проверялась в браузере, админка — запросами через прокси и по SSR-ответам. Автоматических тестов для них нет.
