# 08. Конвенции и типовые задачи

## Общие правила

- Аннотации типов в Python обязательны везде, включая возвращаемые значения. На фронте — TypeScript без `any`.
- Комментарии пишутся только там, где код неочевиден. В проекте их три: порядок запуска в compose, причина прокси в конфиге Nuxt и причина опроса файлов. Комментария вида «получаем список номеров» над функцией получения списка номеров быть не должно.
- Заготовок на будущее нет: ни закомментированного кода, ни пометок TODO, ни функций, которые никто не вызывает.
- Тексты интерфейса и сообщения об ошибках — на русском. Идентификаторы, имена файлов и slug — латиницей.
- Новые слои не вводятся. Раскладка backend и frontend зафиксирована, см. [04-backend.md](04-backend.md) и [06-frontend.md](06-frontend.md).

## Как добавить поле в номер

1. Колонка в `Room` в [models.py](../backend/app/models.py).
2. Поле в `RoomOut` в [schemas.py](../backend/app/schemas.py) — иначе оно не попадёт в ответ API.
3. Значение в каждом из шести словарей в [seed.py](../backend/seed.py).
4. Поле в интерфейсе `Room` в [types.ts](../frontend/app/types.ts).
5. Вывод в [RoomCard.vue](../frontend/app/components/RoomCard.vue) или на странице карточки номера.
6. `docker compose down -v && docker compose up --build` — без пересоздания базы колонка не появится, потому что `create_all` не изменяет существующие таблицы.

## Как добавить эндпоинт

Обработчик кладётся в существующий роутер по смыслу ресурса. Новый файл в `routers/` создаётся только вместе с новой сущностью, и тогда его нужно подключить в [main.py](../backend/app/main.py).

Шаблон обработчика: сессия приходит через `Depends(get_db)`, форма ответа задаётся через `response_model`, ошибки поднимаются как `HTTPException` с русским текстом в `detail`.

Разделение ответственности за валидацию: всё, что видно из тела запроса, проверяет Pydantic и возвращает 422; всё, для чего нужен запрос в базу, проверяет роутер и возвращает 400 или 404.

## Как добавить страницу

Файл в [pages/](../frontend/app/pages/) — маршрут появится сам. Данные тянутся через `useFetch` по относительному пути `/api/...`. Ссылка на страницу добавляется в навигацию в [AppHeader.vue](../frontend/app/components/AppHeader.vue).

Заголовок вкладки задаётся вызовом `useHead` в блоке `script setup`.

## Как добавить стиль

Сначала посмотрите, нет ли подходящего общего класса в [main.css](../frontend/app/assets/css/main.css): `.container`, `.section`, `.grid`, `.card`, `.button`, `.field`, `.notice`, `.tag`. Цвета и отступы берутся из переменных (`var(--accent)`, `var(--space-3)`), а не пишутся числами. Всё специфичное для одного компонента живёт в его `<style scoped>`.

## Чего лучше не ломать

| Что | Почему |
|---|---|
| Правило `routeRules` в [nuxt.config.ts](../frontend/nuxt.config.ts) | Уберёте прокси — фронт перестанет видеть API, и придётся вводить CORS и абсолютные адреса |
| Условие `service_healthy` у backend | Backend начнёт стартовать раньше базы |
| Проверка счётчика в [seed.py](../backend/seed.py) | Каждый перезапуск начнёт дублировать номера |
| Анонимный том на `node_modules` | Контейнер frontend останется без зависимостей |
| Совпадение имён полей `BookingCreate` и `Booking` | Сломается распаковка при создании заявки |
| Пустой [conftest.py](../backend/conftest.py) | Команда `pytest` перестанет находить пакет приложения |
