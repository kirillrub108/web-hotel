# 08. Конвенции и типовые задачи

## Общие правила

- Аннотации типов в Python обязательны везде, включая возвращаемые значения. На фронте — TypeScript без `any`.
- Комментарии пишутся только там, где код неочевиден: порядок запуска в compose, причина `-h` в healthcheck, почему `&` вместо `and` при сравнении пароля, зачем EXCLUDE-ограничение. Комментария «получаем список номеров» над функцией получения списка номеров быть не должно.
- Осознанные упрощения с известным пределом помечаются комментарием `ponytail:` с условием, когда их чинить. Сейчас таких два: счётчики ограничения частоты в памяти процесса и «сегодня» по UTC в проверке даты заезда.
- Заготовок на будущее нет: ни закомментированного кода, ни пометок TODO, ни функций, которые никто не вызывает.
- Тексты интерфейса и сообщения об ошибках API — на русском. Идентификаторы, имена файлов и slug — латиницей.

## Как добавить поле в номер

1. Колонка в `Room` в [models.py](../backend/app/models.py).
2. Миграция: `docker compose exec backend alembic revision --autogenerate -m "rooms: этаж"`. Для колонки `NOT NULL` в таблице с данными задайте `server_default` в миграции, иначе она не применится к существующим строкам.
3. Поле в `RoomOut` в [schemas.py](../backend/app/schemas.py), иначе оно не попадёт в ответ API.
4. Значение в словарях номеров в [seed.py](../backend/seed.py), чтобы пустая база наполнялась полностью.
5. Поле в интерфейсе `Room` в [types.ts](../frontend/app/types.ts).
6. Вывод в [RoomCard.vue](../frontend/app/components/RoomCard.vue) или на странице номера.
7. `docker compose restart backend`: миграция применится при старте, данные сохранятся.

## Как добавить эндпоинт

Обработчик кладётся в существующий роутер по смыслу ресурса. Новый файл в `routers/` появляется только вместе с новой сущностью, и его нужно подключить в [main.py](../backend/app/main.py).

Шаблон обработчика: сессия через `Depends(get_db)`, форма ответа через `response_model`, ошибки как `HTTPException` с русским текстом в `detail`.

Закрытый эндпоинт админки получает `dependencies=[Depends(require_admin)]`. Эндпоинт, который пишет в базу по запросу анонимного посетителя, получает ограничители частоты, как `create_booking`.

Разделение проверок: всё, что видно из тела запроса, проверяет Pydantic и отвечает 422; всё, для чего нужна база, проверяет роутер и отвечает 400, 404 или 409. Правило, которое должно выдерживать гонку запросов, оформляется ограничением базы, а не проверкой в коде.

## Как добавить страницу

Файл в [pages/](../frontend/app/pages/), маршрут появится сам. Данные — через `useFetch` по относительному пути `/api/...`, с явной обработкой `error`. Заголовок вкладки — через `useHead`. Публичная страница добавляется в навигацию в [AppHeader.vue](../frontend/app/components/AppHeader.vue), служебная получает `robots: noindex`.

## Как добавить стиль

Сначала проверьте общие классы в [main.css](../frontend/app/assets/css/main.css). Цвета и отступы берутся из переменных (`var(--accent)`, `var(--space-3)`), а не пишутся числами. Всё специфичное для компонента живёт в его `<style scoped>`.

## Чего лучше не ломать

| Что | Почему |
|---|---|
| Правило `routeRules` в [nuxt.config.ts](../frontend/nuxt.config.ts) | Без прокси фронт перестанет видеть API, а cookie админки перестанет доходить до backend |
| Ограничение `bookings_no_overlap` | Два администратора смогут подтвердить пересекающиеся заявки |
| `-h 127.0.0.1` в healthcheck базы | Backend начнёт стартовать до конца инициализации тома |
| Порядок `alembic upgrade head && python seed.py` | Сид упадёт на несуществующих таблицах |
| Порты `127.0.0.1:8000` и `127.0.0.1:5432` | API и база станут доступны из сети в обход прокси |
| Проверка `ADMIN_PASSWORD` в начале `login` | Пустой пароль начнёт пускать в админку |
| Совпадение имён полей `BookingCreate` и `Booking` | Сломается распаковка при создании заявки |
| Установка окружения в начале [conftest.py](../backend/conftest.py) | Тесты пойдут в рабочую базу вместо `kivana_test` |
