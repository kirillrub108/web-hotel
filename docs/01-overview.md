# 01. Обзор проекта

## Что это

Сайт гостиницы Kivana. Гость смотрит номера, фильтрует их по числу мест и цене, открывает карточку и оставляет заявку на бронирование. Администратор входит в `/admin`, созванивается с гостем и подтверждает или отменяет заявку.

Подтверждённая заявка закрывает даты номера: новую заявку на пересекающиеся даты сайт не примет. Неподтверждённые заявки даты не закрывают, иначе любой мог бы занять календарь фальшивыми заявками.

Оплаты, личного кабинета гостя и редактирования номеров через интерфейс в системе нет. Данные гостиницы и номеров задаются в [seed.py](../backend/seed.py).

## Какую задачу решает код

| Задача | Где решается |
|---|---|
| Хранить гостиницу, номера и заявки | PostgreSQL, [models.py](../backend/app/models.py), миграции в [backend/migrations/](../backend/migrations/) |
| Отдавать данные машинам | FastAPI, роутеры в [backend/app/routers/](../backend/app/routers/) |
| Показывать их людям | Nuxt SSR, страницы в [frontend/app/pages/](../frontend/app/pages/) |
| Принимать и проверять заявку | [bookings.py](../backend/app/routers/bookings.py), [schemas.py](../backend/app/schemas.py) |
| Не допустить двойной брони | ограничение `bookings_no_overlap` в [0001_initial.py](../backend/migrations/versions/0001_initial.py) |
| Пускать в админку только администратора | [security.py](../backend/app/security.py), [admin.py](../backend/app/routers/admin.py) |
| Поднимать всё одной командой | [docker-compose.yml](../docker-compose.yml) |

## Стек и почему именно он

| Технология | Версия | Почему выбрана |
|---|---|---|
| Python | 3.12 | Аннотации типов без обратной совместимости, `StrEnum` из стандартной библиотеки |
| FastAPI | 0.115.6 | Валидация тела запроса и OpenAPI получаются из тех же аннотаций |
| SQLAlchemy | 2.0, синхронный | Синхронный код короче: нет `await` на каждой строке. Нагрузки, которая оправдала бы асинхронность, у сайта гостиницы нет |
| Alembic | 1.20 | Схема меняется миграциями, заявки гостей при этом не теряются |
| Pydantic | v2 | Одни и те же классы описывают ответ API и проверку заявки |
| PostgreSQL | 16 | EXCLUDE-ограничение по диапазону дат решает двойное бронирование на уровне базы |
| Nuxt | 4 | SSR из коробки, файловый роутинг, встроенный прокси в nitro |
| TypeScript | 5.9 | Типы ответов API описаны один раз в [types.ts](../frontend/app/types.ts) |
| Docker Compose | — | Три сервиса, один файл, ноль установок на хосте |

## Осознанно не взято

- **Пользователи и роли.** Администратор один, логин и пароль задаются переменными окружения. Таблица пользователей, хеши паролей и роли понадобятся, когда администраторов станет несколько.
- **JWT.** Сессия — подписанная HMAC cookie с httpOnly. Токен в JavaScript не попадает, отзывать его не нужно: срок жизни двенадцать часов.
- **Сервисный слой и репозитории.** Запросы живут прямо в роутерах. Четыре роутера и десять эндпоинтов не окупают ещё два слоя абстракции.
- **CORS-middleware.** Не нужен: браузер и SSR ходят на тот же origin, см. [02-architecture.md](02-architecture.md).
- **Redis.** Счётчики ограничения частоты живут в памяти процесса. Этого хватает, пока uvicorn работает одним процессом.
- **Продакшен-сборка и reverse proxy.** Проект запускается в dev-режиме; см. [07-infrastructure.md](07-infrastructure.md) и [09-tech-debt.md](09-tech-debt.md).
- **Tailwind и UI-киты.** Один файл [main.css](../frontend/app/assets/css/main.css) с переменными плюс scoped-стили компонентов.
