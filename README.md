## О проекте

Сайт небольшой городской гостиницы. Гость смотрит номера, фильтрует их по числу мест и цене, открывает карточку и оставляет заявку. Администратор входит в `/admin`, видит заявки и подтверждает или отменяет их. Подтверждённая заявка закрывает даты номера для новых заявок.

Оплаты и личного кабинета гостя нет: заявка остаётся заявкой, а подтверждение администратор делает после звонка гостю.

## Стек технологий

| Слой | Технология |
|---|---|
| Backend | Python 3.12, FastAPI 0.115, SQLAlchemy 2.0 (sync), Pydantic v2, Alembic |
| Frontend | Nuxt 4 (SSR), Vue 3, TypeScript |
| База данных | PostgreSQL 16 |
| Инфраструктура | Docker Compose, три сервиса |

## Возможности

- Каталог из шести категорий номеров с фильтрами по вместимости и максимальной цене; фильтрация выполняется запросом к базе.
- Карточка номера с формой заявки: проверки на клиенте и повторно на сервере, включая дату в прошлом, формат телефона и вместимость.
- Админка на `/admin`: вход по логину и паролю из окружения, список заявок с фильтром по статусу и постраничным выводом, подтверждение и отмена.
- Защита от двойного бронирования: пересечение подтверждённых заявок запрещено ограничением PostgreSQL, поэтому его не пропустит даже гонка двух запросов.
- Ограничение частоты заявок и попыток входа: по IP и общий потолок на весь сайт.
- Миграции Alembic: схема меняется без потери данных.
- Понятные страницы ошибок на русском и отдельное сообщение, если backend недоступен.
- SSR, Swagger на `/docs`, изображения локальные, внешних CDN нет.

## Быстрый старт

### Требования

- Docker с плагином Compose

Python и Node.js на хост ставить не нужно.

### Запуск

```bash
git clone <url-репозитория>
```

```bash
cd web-hotel && docker compose up --build
```

Сайт работает без файла `.env`. Админка без пароля выключена. Чтобы её включить, создайте `.env` из примера и задайте `ADMIN_PASSWORD` и `SECRET_KEY`:

```bash
cp .env.example .env
```

| Адрес | Что там |
|---|---|
| <http://localhost:3000> | сайт гостиницы |
| <http://localhost:3000/admin> | админка |
| <http://localhost:8000/docs> | Swagger, открыт только с этой машины |
| `127.0.0.1:5432` | PostgreSQL, открыт только с этой машины |

При старте backend по очереди применяет миграции, наполняет пустую базу и запускает сервер. Повторный запуск данные не дублирует.

Остановить и удалить все данные:

```bash
docker compose down -v
```

## Конфигурация

Все переменные необязательны: `docker-compose.yml` подставляет значения по умолчанию. Справка с комментариями лежит в `.env.example`.

| Переменная | По умолчанию | Описание |
|---|---|---|
| `POSTGRES_USER` | `hotel` | Пользователь PostgreSQL |
| `POSTGRES_PASSWORD` | `hotel` | Пароль PostgreSQL |
| `POSTGRES_DB` | `hotel` | Имя базы |
| `ADMIN_USERNAME` | `admin` | Логин администратора |
| `ADMIN_PASSWORD` | пусто | Пароль администратора; пока пуст, вход отключён |
| `SECRET_KEY` | генерируется при старте | Ключ подписи сессии; без него вход сбрасывается при каждом перезапуске backend |
| `COOKIE_SECURE` | `false` | `true`, когда сайт открывается по HTTPS |
| `WATCH_POLLING` | `true` | Опрос файлов dev-сервером Nuxt; нужен на Windows |

Сгенерировать `SECRET_KEY`:

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

## API

Все маршруты живут под префиксом `/api`. Полное описание со схемами — в Swagger.

| Метод | Маршрут | Описание |
|---|---|---|
| `GET` | `/api/health` | Проверка живости |
| `GET` | `/api/hotel` | Данные гостиницы |
| `GET` | `/api/rooms` | Список номеров, фильтры `capacity` и `max_price` |
| `GET` | `/api/rooms/{slug}` | Один номер |
| `POST` | `/api/bookings` | Создание заявки |
| `POST` | `/api/admin/login` | Вход, ставит cookie сессии |
| `POST` | `/api/admin/logout` | Выход |
| `GET` | `/api/admin/me` | Проверка сессии |
| `GET` | `/api/admin/bookings` | Заявки: фильтр `status`, страницы `limit` и `offset` |
| `PATCH` | `/api/admin/bookings/{id}` | Смена статуса: `new`, `confirmed`, `cancelled` |

Ответы на заявку:

| Код | Когда |
|---|---|
| `201` | Заявка создана со статусом `new` |
| `400` | Номер снят с продажи или гостей больше вместимости |
| `404` | Номера нет |
| `409` | Даты пересекаются с подтверждённой заявкой |
| `422` | Некорректные данные: даты, телефон, почта, имя |
| `429` | Слишком много заявок за десять минут |

Пример:

```bash
curl "http://localhost:8000/api/rooms?capacity=4&max_price=13000"
```

## Тесты

```bash
docker compose exec backend pytest
```

Двадцать восемь тестов покрывают каталог, все ветки заявки, пересечение дат, вход, подпись сессии, работу админки и ограничение частоты. Тесты создают отдельную базу `hotel_test`, накатывают на неё миграции, наполняют данными перед каждым тестом и удаляют в конце. Рабочая база не затрагивается.

## Разработка

Оба сервиса работают в dev-режиме, исходники смонтированы в контейнеры. Uvicorn перезапускается по `--reload`, Nuxt пересобирает страницы на лету.

Bind-mount на Windows не отдаёт события inotify, поэтому dev-сервер Nuxt опрашивает файлы. На Linux и macOS опрос можно выключить через `WATCH_POLLING=false`.

Изменить схему базы: поменяйте модель в `models.py`, создайте миграцию и перезапустите backend.

```bash
docker compose exec backend alembic revision --autogenerate -m "описание изменения"
```

Проверьте сгенерированный файл в `migrations/versions/` перед коммитом. Autogenerate не отслеживает CHECK-ограничения и ограничение `bookings_no_overlap`, их изменения пишутся в миграции вручную. Команда `alembic check` сверяет модели с базой.

Данные гостиницы и номеров задаются в `backend/seed.py` и попадают только в пустую базу.
